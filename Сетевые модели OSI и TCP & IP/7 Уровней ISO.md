# Таблица

7. **Прикладной уровень**
	**Функция:** обеспечивает взаимодействие пользовательских приложений с сетью. Этот уровень **не передаёт** данные сам - он предоставляет **интерфейс** для протоколов прикладного уровня.
	
	На практике: когда вы вводите URL в браузере, протокол HTTP (уровень 7) формирует запрос и передаёт его вниз по стеку.
	
	`Пример из жизни: это как «заказ блюда в ресторане» - вы говорите, что хо тите, а кухня (нижние уровни) занимается приготовлением.`
	
	- HTTP веб 
	- FTP файлы 
	- SMTP почта 
	- DNS имена 
	- SSH удаленный доступ

6. **Уровень представления**
		
	Функция: отвечает за форматирование данных - кодирование, шифрование и сжатие. Приводит данные к виду, понятному приложению на приёмной стороне.
	
	На практике: когда ваш браузер устанавливает HTTPS соединение, именно этот уровень шифрует данные через SSL/TLS.
	
	Пример из жизни: это «переводчик» - переводит «язык» отправителя в «язык» получателя.
	
	- SSL/TLS шифрование
	- JPEG/PNG сжатие изображения
	- ASCII/Unicode кодировка

5. **Уровень сеанса**
	Функция: устанавливает, поддерживает и корректно завершает сеансы связи между приложениями. Управляет диалогом: кто говорит, когда, и как завершить.
	
	На практике: когда вы загружаете веб-страницу - это один сеанс. Если обрывается интернет и восстанавливается - сеанс может быть продолжен.
	
	Пример из жизни: это «ведущий переговоров» - контролирует, кто сейчас говорит и в какой очерёдности.
	
	- NetBIOS - сеанс
	- RPC вызов процедур
	- PPTP VPN-тоннели

4. **Транспортный уровень**
	Функция: обеспечивает надёжную передачу данных между хостами конечно-в-конец (end-to-end). Делит данные на сегменты, контролирует поток, выполняет повторную передачу при ошибках.
	
	TCP vs UDP: TCP - надёжный, с подтверждением (веб, почта, файлы). UDP - быстрый, без гарантий (видеоконференции, игры, DNS).
	
	Пример из жизни: ТСP - это почтовый курьер, который возвращается, если не расписались: UDP - это вкладывающий записки в портфель школьник.
	
	- ТСP - надежно
	- UDP - быстро
	- Порт - адрес процесса

3. Сетевой уровень

	**Функция:** организует **маршрутизацию** пакетов - определяет путь от источника к получателю через промежуточные сети. Адресация на этом уровне - по **IP-адресу**
	
	**На практике:** маршрутизатор работает на сетевом уровне. Когда пакет отправляется из Москвы в Берлин, каждый маршрутизатор на пути принимает решение о следующем «прыжке» (hop).
	
	**Пример из жизни**: это «навигатор Google Maps - знает адрес назначения и выбирает оптимальный маршрут.
	
	- IP - адресация
	- ICMP - диагностика (ping)
	- OSPF/BGP - маршрутизация
	- ARP - IP -> MAC

2. Канальный уровень

	**Функция:** передача данных между соседними узлами по физическому каналу. Обеспечивает обнаружение и исправление ошибок, контроль доступа к среде (МАС). Адресация - по **МАС-адресу**
	
	**На практике:** коммутатор работает на канальном уровне. Он коммутирует кадры по МАС-адресу внутри локальной сети.
	
	**Пример из жизни:** это «почтальон для соседней улицы» - знает всех соседей и доставляет внутри двора.
	
	Ethernet - кабельная ЛВС
	Wi-Fi - беспроводная ЛВС
	MAC -адрес устройства

1. Физический уровень
	
	**Функция:** передача **битов** по физической среде - электрические сигналы в проводах, световые импульсы в оптоволокне, радиоволны в беспроводных сетях.
	
	**На практике:** хаб (Hub) работает на физическом уровне - он просто ретранслирует сигнал во все порты без анализа,
	
	**Пример из жизни:** это «провод и розетка» - сама среда, по которой бегут биты.
	
	- RJ-45 - витая пара
	- Fiber - оптоволокно
	- Radio - радиоволны
